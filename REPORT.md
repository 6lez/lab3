# Лабораторная №3. Линейные модели

## Данные и подготовка

| Файл | Цель | Признаки | Train / test |
| --- | --- | ---: | ---: |
| `Student_Performance.csv` | `Performance Index`, баллы | 5 | 8 000 / 2 000 |
| `german.csv` (разделитель `;`) | `Creditability`, класс 0 или 1 | 20 | 800 / 200 |

В обеих таблицах нет пропусков. У студентов `Extracurricular Activities` заменён на 1 для `Yes` и 0 для `No`. Использованы все строки, цель исключена из признаков. В кредитных данных целевой столбец — первый; остальные взяты в исходной числовой кодировке, без one-hot-кодирования.

Каждую таблицу разбили один раз: `train_test_split(test_size=0.2, random_state=42)` с перемешиванием. Для кредитных данных применили `stratify` по цели: класс 1 составил 560 из 800 строк в train и 140 из 200 в test. Все классификаторы получили одни и те же строки в одном и том же порядке.

Каждый признак центрировали и делили на его стандартное отклонение (`StandardScaler`). Среднее и масштаб определяли **только на train**, затем применяли к test; целевые значения не масштабировали. Так размер `Credit_Amount`, например, не определяет величину градиента или расстояние kNN просто из-за единиц измерения. Обе собственные модели возвращают коэффициенты в исходных единицах входных признаков: `w = w_std / scale`, `b = b_std − mean @ w`.

## Гипотезы и эксперименты

1. **Успеваемость.** Проверяли, насколько линейная комбинация пяти признаков лучше прогноза одним числом — средним баллом по train. Веса и смещение начинались с нуля; за эпоху выполняли один шаг по градиенту MSE на всех 8 000 обучающих строках. Шаг — `0.05`, число эпох — `800`.
2. **Кредитоспособность.** Проверяли, хватит ли линейного правила для ранжирования заявок лучше, чем по листьям дерева или голосам соседей. Для своей логистической регрессии использовали нулевую инициализацию, пакетный градиент BCE, шаг `0.1` и `1000` эпох без регуляризации. Вероятность — сигмоида линейного прогноза; класс 1 предсказывали при `p ≥ 0.5`.
3. **Сравнение.** Обучили дерево без ограничения глубины (`DecisionTreeClassifier(random_state=42)`) и kNN (`k=5`, евклидово расстояние, равные голоса). Для независимой проверки обучили также `sklearn.linear_model.LogisticRegression` без регуляризации, с решателем `lbfgs`, `tol=1e-9`, `max_iter=1000`. Эта модель не участвует в собственном градиентном спуске. Параметры по test не подбирались.

На каждом шаге остаток `r` равен `Xw + b − y` для линейной модели и `p − y` для логистической. Градиенты BCE по весам и смещению — `Xᵀr / n` и `mean(r)`; у MSE оба выражения умножаются на 2. В историю записывали потерю на train **после** обновления весов и смещения:

| Модель и потеря | Эпоха 1 | Эпоха 10 | Эпоха 100 | Последняя эпоха |
| --- | ---: | ---: | ---: | ---: |
| Линейная, MSE | 2777.910810 | 421.081880 | 4.169738 | 4.169736 (800) |
| Логистическая, BCE | 0.682462 | 0.612727 | 0.492152 | 0.482132 (1000) |

У линейной регрессии уже к сотой эпохе MSE почти перестала меняться. У логистической продолжение обучения после сотой эпохи снизило BCE ещё примерно на 0.010.

## Метрики

**Регрессия, 2 000 тестовых строк.** Тестовая MSE собственной модели — **4.082628** (RMSE ≈ **2.02 балла**), у прогноза средним по train — **370.773038**.

**Классификация, 200 тестовых строк.** ROC-AUC вычислялась по вероятностям класса 1, остальные метрики — по меткам. В Precision, Recall и F1 положительный класс — `Creditability = 1`.

| Модель | ROC-AUC | Accuracy | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Собственная логистическая | 0.8081 | 0.7700 | 0.8013 | 0.8929 | 0.8446 |
| Дерево решений | 0.6226 | 0.6850 | 0.7730 | 0.7786 | 0.7758 |
| kNN | 0.7412 | 0.7200 | 0.7692 | 0.8571 | 0.8108 |
| Логистическая sklearn (контроль) | 0.8081 | 0.7700 | 0.8013 | 0.8929 | 0.8446 |

## Выводы

- Линейная зависимость описывает баллы существенно лучше константы. Ошибка на новых строках близка к обучающей (MSE 4.083 против 4.170), несмотря на то что test не использовался для обучения.
- На этом разбиении собственный классификатор опередил дерево и kNN по всем пяти метрикам, а с независимым решением той же логистической задачи метрики совпали. Неограниченное дерево подогналось к train (Accuracy 1.0), но на test выдало только вероятности 0 и 1: внутри этих двух групп заявки не ранжируются. У kNN с пятью соседями оценки тоже дискретны; кроме того, разность числовых кодов категорий не обязательно отражает сходство заявок. Это возможные причины отставания, а не вывод о любых деревьях или kNN.
- Высокий Recall логистической модели относится к более частому классу: правильно найдены 125 из 140 объектов класса 1, но только 29 из 60 объектов класса 0. Если важнее не пропускать класс 0, стоит выбирать порог по стоимости ошибок на отдельной валидационной выборке, не на этом test.

## Воспроизводимость

Команды из корня репозитория (проверено с Python 3.11.2; версии NumPy, Pandas, SciPy и scikit-learn закреплены в `requirements.txt`):

```bash
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run_experiments.py
```

Скрипт читает оба CSV из репозитория, печатает точки истории потерь и матрицу ошибок, затем записывает неокруглённые тестовые метрики в `experiment_results.json`. Поле `BaselineComparisonResult.logistic_regression` содержит метрики собственной модели. В JSON они записаны под ключом `own_logistic`, а под `logistic_regression` — результат отдельной контрольной модели sklearn.
